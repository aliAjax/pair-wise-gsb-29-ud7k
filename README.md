# 骑手交班核对台

晚间换班时，骑手手里还有未送完的订单、代收现金混在个人账户里。本工具把电话点单式的交接
变成一条有闸门的核对流程：**先核平现金 → 再按剩余路线顺序和冷冻格容量确认承接 → 差额经班长
放行后才能完成换班；装不下的冷链单留在原骑手并写明原因。**

## 流程规则

1. **现金核对**：逐单登记已收现金（金额按「分」存储避免浮点误差），录入从原骑手个人账点出的
   实交金额。应收与实交一致才算核平；出现长款/短款立即停在「班长复核」，不能继续。
2. **班长复核**：差额需班长填写姓名和处理意见后放行（按实交金额记账，差额不被抹零）；
   也可退回重新点现金。
3. **路线与冷冻格确认**：每单指定接班骑手后，按剩余站序从小到大逐单装格，冷链单占用接班人
   车上冷冻格（以车上已有冷链单为起点），常温单不占格。装不下的单**留在原骑手**并给出
   「容量不足」原因，不影响其余单。
4. **完成换班**：接单成功的单转给接班人；留单原因、现金差额、班长意见全部写入交班记录。

## 分层结构（路线判断、交班记录、页面分开）

- `src/domain/` —— 纯领域逻辑，不依赖 Vue / localStorage
  - `cash.ts` 现金核对（分/元换算、差额计算）
  - `route.ts` 路线判断：按站序装格、冷冻格容量评估
  - `handoff.ts` 交班状态机：cash → review → capacity → done 闸门
  - `types.ts` 骑手、订单、指派模型
- `src/store/handoverStore.ts` —— 记录层：骑手/订单/交班记录的 localStorage 持久化
- `src/pages/`
  - `CheckDeskPage.vue` 交班核对台（流程操作页面）
  - `HandoffLogsPage.vue` 交班记录（只读历史，可只看有差额的记录）

## 使用

```bash
npm install
npm run dev       # 本地开发
npm run build     # 类型检查 + 构建
npm test          # 领域逻辑冒烟测试（16 项闸门/容量断言）
```

数据保存在浏览器 localStorage（`handover-desk-*-v1` 三个键），内置一名晚班骑手带 6 单的
演示数据，其中冷链单数量刻意超过接班人冷冻格，便于直接看到「留单并写明原因」的效果。
